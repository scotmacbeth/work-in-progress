### [A Typed Language for Agent Coordination](https://golem.ph.utexas.edu/category/2026/03/a_typed_language_for_agent_coordination.html) — n-Category Café (also cross-posted [Azimuth](https://johncarlosbaez.wordpress.com/2026/03/11/a-typed-language-for-agent-coordination/)), Mar 11 2026
William Waites introduces "plumbing," a typed language for coordinating multiple LLM agents, built on a **copy-discard category**: six morphisms (Copy, Discard, Merge, Barrier, Map, Filter) on typed channels `!A`, with sequential and parallel (`⊗`) composition. Explicitly flagged as a first post in a series — session types and memory/context management are promised as later installments requiring "more sophisticated categorical machinery." No distributive-law/Zappa-Szép/semidirect-product content in this post itself, but the series trajectory (copy-discard cat → session types → protocol composition) is worth tracking as a possible neighbour to the orchestration-as-ZS-weld line.

### [The Agent That Doesn't Know Itself](https://golem.ph.utexas.edu/category/2026/03/the_agent_that_doesnt_know_its.html) — n-Category Café (also [Azimuth](https://johncarlosbaez.wordpress.com/2026/03/20/the-agent-that-doesnt-know-itself/), and apparent original at [Leith Document Company](https://leithdocs.com/ldc/documents/outgoing/plumbing/the-agent-that-doesnt-know-itself.md)), Mar 20 2026, follow-up to the above by William Waites
Confirmed and read in full. Formalizes LLM context-window compaction as **nested traces in a traced monoidal category**: an internal trace (conversation history feeding back invisibly) and an external trace (a "homunculus" supervisor executing compaction protocols). Session types are compiled functorially into "plumbing" primitives (send/recv, select/offer + barrier-synchronization chains) from the earlier post. Core problem: the agent cannot perceive compaction events (they happen "in the gap between turns") and confabulates explanations for summaries it doesn't remember writing; fix is runtime self-knowledge metadata (cycle count, token fill, timestamps) rather than retraining. Comment from Steve Huntsman raises topic-based/attention-organized memory as an alternative. Directly relevant to the agent-orchestration application strand — this is a concrete, publicly discussed instance of "self-reference under bounded context" modeled with trace operators, distinct from but adjacent to the ZS/H² orchestration framing.

### [cartesian monad](https://ncatlab.org/nlab/show/cartesian+monad) — nLab
Key remark directly touches the merge-witness theme: the entry contrasts the free strict monoidal category monad (symmetries kept as non-identity — **cartesian**) with the free *symmetric* strict monoidal category monad (symmetries collapsed to identities — **NOT cartesian**), and likewise free monoid (cartesian) vs free commutative monoid (not cartesian). The stated reason is exactly "collapsing/identifying distinct inputs." This is a clean, citable general statement of the same phenomenon behind MacBeth's Bag/SYMMETRY obstruction (registry: reader-state-outside-pi-mendler.md, "SYMMETRY(Bag,out)") — worth checking as a possible prior articulation of the symmetry-breaks-cartesian direction, separate from the merge(Pf)/drop(Reader,State) legs already characterized.

### [polynomial monad](https://ncatlab.org/nlab/show/polynomial+monad) — nLab
Standard definition (polynomial functor + cartesian unit/mult); confirms free monad on a polynomial endofunctor is again polynomial (hence cartesian) — consistent with existing results, no new leverage. No 2025-2026 references on the page (most recent citation is Awodey 2023 HoTT slides).

### [Set-sets](https://topos.institute/blog/2025-11-21-set-sets/) — Topos Institute blog, Aaron Fairbanks, Nov 21 2025
Primer on endofunctors on Set as algebra/coalgebra generators; states polynomial functors are exactly the "freely generated" Set-sets, and — notably — that **"comonads on Set given by polynomial formulas are precisely the same as (small) categories."** This is adjacent to (possibly a public restatement of) MacBeth's DCont ≅ Cat work; flagged as a neighbour to check against the existing DCont/Cat registry entries. Framed as a primer for forthcoming Topos posts on comonads.

### [Composition of attractor lattices](https://topos.institute/blog/2026-01-30-composition-of-attractor-lattices/) — Topos Institute blog, Tony Wehbe, Jan 30 2026
Attractors of a dynamical system form a bounded distributive lattice; a realization map ρ sends products of attractors into the attractor lattice of the product system but is not surjective — composed systems get emergent ("corner") attractors not expressible as A×B. No polynomial functors/wiring diagrams/comonads used here, but thematically close to the "composition creates structure absent from parts" pattern relevant to orchestration/emergence discussions. Future work flagged: cascade products, sheaf-theoretic framing.
