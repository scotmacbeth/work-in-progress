Dear Alastair,

Yesterday I promised composition. I'm going to make you wait one more day, because there
is a smaller thing I want you to see first, and it installs the single most useful reflex
in the whole subject.

Quick recap, so this page stands alone. A CONTAINER is a set of shapes S, and for each
shape s a set of positions P(s). Shape = what kind of structure this is (a list of length
3). Positions = the slots you can put things in ({0,1,2}). We write it S <| P. It becomes
a functor by filling the slots:

    [[ S <| P ]] X  =  Sum_{s in S} ( P(s) -> X )

Pick a shape; label every position with an element of X. That functor is the EXTENSION of
the container.

Now: containers form a category, and that category has PRODUCTS. So what IS the product of
two containers? Take C = S <| P and D = T <| Q. The product C x D ought to be "a
C-structure AND a D-structure, side by side, over the same elements". So:

    Shapes of C x D:   S x T

Obvious. Pick a shape of each. No argument. And:

    Positions of C x D at the shape (s,t):   P(s) + Q(t)

A disjoint SUM. Read that again. The PRODUCT of two containers has, as its positions, the
SUM of the position-sets.

If your reaction is "that's backwards, surely" — good. That is the correct reaction, and
it is why I'm writing this page instead of the one about composition. It looks like
someone typed the wrong symbol. It is not a typo. It is a law of exponents.

The resolution is three lines. A labelling of the positions at (s,t) is a function out of
P(s) + Q(t). But what IS a function out of a disjoint sum? To define f on A + B you must
say what f does on A, and say what f does on B — and that is all you must say, and the two
halves never interfere. To give one function out of a sum is exactly to give a PAIR of
functions:

    X^(A + B)  =  X^A  x  X^B

Every schoolchild knows this law. It is the same law. Watch it work:

    [[ C x D ]] X  =  Sum_{(s,t)}  ( (P(s) + Q(t)) -> X )
                   =  Sum_{(s,t)}  ( P(s) -> X )  x  ( Q(t) -> X )
                   =  ( Sum_s (P(s) -> X) )  x  ( Sum_t (Q(t) -> X) )
                   =  [[C]] X  x  [[D]] X

A sum of positions went in; a product of structures came out. The extension turned the sum
upside down, exactly as the exponential law says it must — and a product of structures is
precisely what we wanted the product to BE.

So here is the reflex, worth more than the theorem: POSITIONS LIVE ON THE LEFT OF AN ARROW.
They are exponents. They are contravariant. Anything you do to a set of positions comes
back to you FLIPPED. Sum in the positions, product in the data. Once you have this you stop
being surprised and start predicting.

One concrete case, to make it real. Let Id = 1 <| {*}: one shape, one position — "a single
element, no structure". Then Lists x Id has shapes N (a length), and positions
{0,...,n-1} + {*}: the n slots, plus one spare. And [[Lists x Id]] X = (list of X) x X. A
list together with one extra element. Count the slots: n + 1. All present. Of course they
are.

(For the record, this contravariance is also why the honest name for the category of
containers is Fam(Set^op) — the "op" is exactly this flip. You need none of that today; I
mention it so that when you meet the name later you will know what it is apologising for.)

The perversity is not perversity. It is a law of exponents, wearing a costume.
